# Architecture

## Scope and authority

This repository is an independent open-source kernel under
`E:/Zero_Base/playground/capability-control-plane`. It does not import the
personal control-plane at `D:/DevConfig/agent-control-plane`, Codex home
directories, Claude loader roots, or `.momo` at runtime. Those systems may later
own an explicit provider adapter; V1 has none.

The control plane is a derived decision surface, not a second source registry:

| Boundary | Owner | V1 responsibility | Forbidden |
| --- | --- | --- | --- |
| Protocol SSOT | `capability-protocol` | all cross-boundary Rust semantics | I/O, secrets, execution |
| Pure engine | `capability-engine` | admission, sparse route, digest, plan | filesystem/network/process |
| Local boundary | `capctl` | rooted read-only JSON and output | writes, shell, client mutation |
| Projections | `xtask` -> `generated/` | mechanical Schema/client mappings | authored policy or semantic defaults |
| Desired state | caller-owned JSON | catalog and policy intent | inferred from status/logs |
| Observed state | caller-owned JSON | evidence for planning | authority or success proof |
| Provider | future adapter owner | opaque authority read/search contract | ambient path dereference |

## Data flow

```text
strict JSON -> decode -> admission -> immutable index -> route(query)
                                  |                      |
                                  +-> digest             +-> decision

desired JSON + observed JSON + policy -> pure diff -> plan with CAS preconditions
```

The route query is untrusted data. It can affect ranking only; it cannot widen
authority or permission. `RouteDecision::Ambiguous` and `NoMatch` are normal,
fail-closed outcomes. Public results contain quantized ordering scores but no
query text, matched terms, or stable query digest. A later assembler must
require an explicit selected ID, recheck the catalog/policy digest, and read
through the owning provider.

## Physical model

The design uses a physical analogy as an engineering aid, not as a claim of
scientific law:

| Physical concept | System object | Invariant |
| --- | --- | --- |
| potential | desired `spec` | only governed desired state can cause work |
| observation | `status`/observed snapshot | stale, deletable, and rebuildable |
| force | admission and reconciliation | deterministic and bounded |
| boundary condition | authority/provider | reads remain owner-scoped |
| time | generation/resource version/digest | stale plans abort and replan |
| feedback | shadow/observed evidence | never becomes desired truth |

The Kubernetes principle absorbed here is level-triggered, idempotent
Observe -> Diff -> Act -> Verify. V1 stops before Act. Events, if introduced
later, may coalesce keys but cannot become truth; startup and overflow must force
a full rescan. We explicitly reject an API-server/etcd/CRD/watch clone until a
measured multi-writer or availability requirement exists.

## Context economics

The index is a bounded working-set selector, not a promise that every skill can
fit in a model prompt. `estimatedTokens` is a conservative local estimate, not a
model tokenizer. Native Codex 2% admission remains the external runtime's
authority. This project records route and assembly evidence without replacing
native rendering, deferred tool search, approval, or sandbox boundaries.

## One semantic source

Every cross-boundary input, decision, plan, and error envelope is a Rust type in
`capability-protocol`. Serde names, strict decoding, JSON Schema, and TypeScript
bindings are derived from those same definitions. Compiled ceilings, identifier
grammar, digest grammar, fixed-width integers, resource kinds, and error codes
live beside the wire types. Cross-resource admission and ranking algorithms
remain in the pure Rust engine. `xtask codegen` is a pure projection step; CI
compares generated bytes and the exact generated file set.

Client adapters may convert transport and host primitives, but they cannot own
permissions, default values, state transitions, or compatibility semantics.
Those changes begin in Rust, require a protocol-version decision, and then flow
outward. Generated files are useful review/build artifacts, never a second SSOT.

Schema and TypeScript are projections, not a replacement for protocol
validation. JSON Schema expresses structural ceilings such as item counts,
collection sizes, identifier grammar, and character-length hints; the Rust
validator remains authoritative for UTF-8 byte ceilings, cross-field policy
relationships, and any semantic rule that JSON Schema cannot express exactly.

For a fixed target, compiler, dependency lock, and selector configuration, route
ordering is deterministic and permutation-stable. Cross-platform byte identity
is a separate release gate and is not claimed by V1. The current index keeps an
admitted working set of `N <= 10,000` descriptors and scores that bounded set;
`topK` bounds returned results and selection, not all intermediate storage.

## Frontend boundary

There is no frontend in V1. When an operator workflow is demonstrated, a future
`apps/` package may use Feature-Sliced Design (`shared`, `entities`, `features`,
`widgets`, `pages`, `app`) and consume read-only plans. It must not become a
second policy owner or make a dashboard a prerequisite for the CLI kernel.
