# Governance

The repository currently uses a single-maintainer bootstrap model. The current
repository owner is the final merger and release authority until a public
maintainer roster is created. This file does not invent names or GitHub handles.

Durable decisions use ADRs. Security boundary changes, new authority types,
runtime writes, network services, plugin execution, database adoption, and
release signing require explicit review and an accepted ADR. A benchmark or
model leaderboard result cannot waive those gates.

The project will move to documented multi-maintainer quorum only after real
maintainers exist. At that point this file must define roles, nomination,
removal, conflict handling, and release key ownership before the new model is
used.
